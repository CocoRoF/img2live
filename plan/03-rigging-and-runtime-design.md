# 03. 리깅·런타임 설계 (See-through 다음 단계의 핵심)

근거: 에이전트 조사 `research/rigging.md` + **직접 확인**(psd2live 헤드리스 산출물 존재·`MOC3` v5 헤더, Bunraku 저장소·논문, image2live2d README).
표기: **(V)** 확인 / **(V†)** 요약 경유 확인 / **(U)** 설계 제안·미검증. 공수·수치 목표는 전부 **추정(U)** 이며 M0 실측 후 재보정한다.

## 0. 먼저 읽을 결론

1. **"리깅은 미해결"이라는 전제는 2026-10 기준 절반만 맞다.** See-through 공개(2026-02) 후 6개월 만에 OSS 가 폭발했다. `psd2live`(Kotlin, GPL-3.0, 2026-09-03 시작, 530 stars)는 레이어 PSD → 메시 + 디포머 + 파라미터 + 물리 + 모션 + `.moc3`/`.cmo3` 를 **헤드리스 CLI 한 번**에 만든다. 에이전트가 **개발 머신(GPU 없음, JDK 21)에서 예제 PSD(24레이어)로 직접 실행해 약 9초에 `.moc3`(헤더 `MOC3` v5)·`model3`·`physics3`·모션 4종이 나오는 것을 확인했고, 산출물 파일이 남아 있어 제가 다시 열어 봤다.** (V)
2. **그러나 "전문가급 자동 리그"는 아무도 못 했고 개발자들이 스스로 그렇게 말한다.** psd2live 예제 = 24 드로어블 / 29 디포머 / 20 파라미터, Cubism 샘플 Hiyori = 134 / 104 / 70. **자동 리그 성공률 통계는 어디에도 없다.** → 현실적 천장은 **Tier 1**(눈 깜빡임·입 열림·호흡·머리카락 흔들림·작은 머리 회전).
3. **진짜 갭은 리그 알고리즘이 아니라 "소재"다.** psd2live 가 요구하는 `eye_close`, `mouth_close`, **완전히 벌린 `mouth_open`**, `tooth-t/b`, `tongue` 를 See-through 는 만들지 않는다. 입이 닫힌 그림이면 "입이 안 열리는데 에러도 없는" 조용한 실패가 난다. → **변형 소재 생성(눈 감김·입 모양)이 img2live 의 실질적 R&D** 이고, 여기가 "최신 생성 모델"이 들어가는 자리다(`02`).
4. **머리 각도 XYZ 는 학습 없는 해석 모델이 실전 해법**이다. StretchyStudio 는 See-through 의 Marigold 깊이를 얼굴 시차에 써 보다가 **더 나빠서 제거**하고 "원통 돔 + 이목구비 보호 영역"으로 갔다. psd2live 는 AngleX×AngleY 9포즈 격자. 생성 키프레임을 레이어에 정합하는 방식은 **공개 구현을 못 찾았다**(연구 트랙).
5. **학계의 직접 경쟁작은 Bunraku 한 편뿐이고 쓸 수 없다**(코드·가중치·라이선스 없음 — 직접 확인). 그러나 **표현 방식이 Cubism 키폼과 동형**이라 우리 설계의 근거가 된다(§2).
6. **핵심 설계 결정: "IRR(중간 리그 표현) = 키폼 데이터"를 중심에 두고, 컴파일러·런타임·내보내기를 모두 IRR 에 대해 교체 가능하게 만든다.** (§2)

## 2. Bunraku 에서 가져올 것: "키폼 = 정점 변위"

(arXiv 2607.27348, V†) Stage 2 는 **레이어별 메시를 알파에서 결정적으로 생성**하고, 5.1M 파라미터 트랜스포머가 **모든 레이어의 모든 정점을 토큰으로** 해 "파라미터 P 의 keypose 값 k 에서 각 정점이 얼마나(방향·log-크기) 움직이는가"를 예측한다. 런타임은 **인접 keypose 사이 선형 블렌드, 파라미터 여러 개는 가산**.

이것은 **Cubism 의 ArtMesh 키폼 모델과 같은 구조**다: "파라미터 바인딩의 키 값들에서의 정점 위치/불투명도/그리기 순서 + 다차원 선형 보간". 그러므로:

- 우리 IRR 을 **키폼 데이터 구조**(Cubism 동형)로 정의하면, **해석 모델(원통 돔 등)·학습 모델(Bunraku 식)·생성 키프레임 정합(Tier 2)** 이 모두 **같은 출력 포맷(키폼)** 을 낸다 → 컴파일러를 갈아 끼워도 런타임·QA·내보내기는 그대로.
- Bunraku 의 한계가 곧 우리의 설계 제약: **다중 파라미터 가산 시 진폭이 커져 "레이어가 벌어짐"**(중앙 비율 1.234) → **파라미터 간 결합(대각 키폼, 진폭 감쇠)을 QA 지표로 잡는다**.
- 모델을 5.1M→571M 로 키워도 개선이 없었다 = **병목은 데이터 다양성**. 우리가 학습형 컴파일러로 가려면 합법적 Live2D 데이터가 선결(→ `04` §5). **MVP 는 학습 없이.**

## 3. 아키텍처: 4개의 교체 가능한 면과 하나의 중심

```
              ┌─────────────── 컴파일러 (레이어 → IRR) ───────────────┐
 layers+depth │ C1 해석 컴파일러(MVP)  C2 psd2live→moc3→IRR 어댑터(기준선) │
 + variants ─►│ C3 학습 변위 컴파일러(후속)  C4 생성 키프레임 정합(R&D)    │
              └───────────────────────────┬──────────────────────────────┘
                                          ▼
                         ┌──────────────  IRR  ──────────────┐
                         │ puppet.json + 아틀라스(WebP)       │   ← 중심 계약
                         │ parts / artmeshes / deformers /    │
                         │ parameters / keyforms / masks /    │
                         │ physics / motions / metadata       │
                         └──┬─────────────┬────────────┬─────┘
                            ▼             ▼            ▼
                    웹 런타임(TS)     QA(수치+VLM)    내보내기
                    (자체, Core 無)   (렌더 시트)     PSD · 투명 영상 · .inp ·
                                                      (게이트) .moc3 lowering
```

- **IRR 은 Cubism 과 동형**으로 설계한다 → `moc3 lowering` 이 기계적(psd2live·image2live2d·Umamo 의 "Puppet → MocLowering" 구조와 같음). 단 **내보내기는 법무 게이트 뒤 3단계**(→ `04`).
- **파라미터 ID 는 Cubism 표준(`ParamAngleX/Y/Z`, `ParamEyeLOpen/ROpen`, `ParamEyeBallX/Y`, `ParamBrowLY/RY`, `ParamMouthForm/OpenY`, `ParamBodyAngleX/Y/Z`, `ParamBreath`, `ParamHairFront/Side/Back` …)을 그대로** 쓴다(법적 문제 없음, VTube Studio 자동 설정이 표준 이름을 전제 — V). 범위도 표준(AngleX/Y/Z ±30, 몸 ±10, 눈 0..1)을 기본으로, 확장은 `ext_` 접두어로 구분.
- **런타임은 자체 구현**한다(TS/WebGL2). Cubism Core 는 쓰지 않는다 → Expandable Application 문제를 구조적으로 회피(→ `04` §1). 범용·단순해야 한다: **키폼 보간 + 워프/회전 디포머 체인 + 클리핑 마스크 + 그리기 순서 + 진자 물리 + 모션 재생** (≈1~2k 줄 규모로 예상, U).
- **런타임 정확도 검증:** psd2live 가 만든 `.moc3` 를 오픈 구현(Ayagami/Purism, 블랙박스 오라클)로 렌더한 결과와 **우리 런타임의 같은 모델 렌더**를 비교한다(C2 어댑터가 있으면 같은 파일을 양쪽에 먹일 수 있다). *(Cubism 보간식·좌표계는 공개 1차 문서가 없어 이 오라클 실험으로 확정 — `04` §8)*

### IRR 스케치 (U, M1 에서 확정)
```jsonc
{
  "schema": "irr/1", "canvas": {"w":2048,"h":2048}, "ai_generated": true,
  "parts":   [{"id":"PartFace","parent":null}],
  "meshes":  [{"id":"face","tex":"atlas0","uv":[...],"idx":[...],"parent":"WarpFaceParallax",
               "mask":["eyewhite_l"],"drawOrder":{"base":410,"keyforms":[...]},
               "keyforms":{"bind":["ParamAngleX","ParamAngleY"],
                           "keys":{"ParamAngleX":[-30,0,30],"ParamAngleY":[-30,0,30]},
                           "forms":[{"pos":[...]} /* 9개: 부모-로컬 정점 */ ]}}],
  "deformers":[{"id":"WarpFaceParallax","type":"warp","parent":"RotHead","grid":[5,5],
                "keyforms":{...}}, {"id":"RotHead","type":"rotation","origin":[..],"keyforms":{...}}],
  "params":  [{"id":"ParamAngleX","min":-30,"def":0,"max":30}],
  "physics": [{"in":[{"p":"ParamAngleX","w":60,"type":"x"}],"out":[{"p":"ParamHairBack","scale":..}],
               "vertices":[{"mobility":..,"delay":..,"accel":..,"radius":..}],"norm":{...}}],
  "motions": {"idle":{...}, "blink":{...}},
  "meta":    {"capability":{"blink":"ok","lipsync":"degraded:no_open_mouth_art"}, "qa":{...}}
}
```
**좌표계 함정(V†, StretchyStudio 가 겪은 것):** ArtMesh 는 위치 배열이 둘(캔버스 픽셀=텍스처용 / 부모 디포머 로컬=렌더링용), **워프 로컬 = 0..1 격자 좌표**, **회전 디포머 로컬 = 자기 피벗 기준 캔버스 픽셀 오프셋**, 0..1 키폼은 **소수 6자리** 필요(1자리면 텍스처가 "씹힘"), 마스크 아트메시도 부모 디포머 체인에 키폼이 있어야 함, **Cubism 은 워프끼리 보간하지 않으므로 얼굴은 하나의 워프에 풍부한 공식**이 낫다. **AngleX(요)에 2D 회전 디포머를 걸면 머리가 목에서 떨어진다 → 요는 워프 키폼만으로, 회전 디포머는 Z축 기울임만.**

## 4. 컴파일러 C1 (해석 컴파일러, MVP) — 단계와 알고리즘

모든 단계는 **결정론적**이고, 입력 = (정규화된 레이어 PSD/PNG + depth + 변형 소재 + RigSpec).

### 4.1 앵커: 랜드마크 대신 레이어 기하로 측정 (V†/U)
See-through 출력은 `face`, `eyewhite`, `irides`, `eyelash`, `eyebrow`, `nose`, `mouth`, `neck`, `ears` 가 이미 분리되어 있으므로 앵커를 **측정**으로 얻는다.
| 앵커 | 산출 | 근거 |
|---|---|---|
| 얼굴 중심/반경 | `face` bbox + 10% | Stretchy / psd2live |
| **머리 피벗(턱)** | **`face` 하단 + `neck` 상단** — 머리+머리카락 합집합 bbox 의 maxY 를 턱으로 쓰면 얼굴 높이의 37–74% 어긋나 AngleZ 가 목 아래 먼 점을 축으로 돎 | Stretchy 실측 (V†) |
| 눈 닫힘선 | `eyewhite` 알파를 아래→위 스캔해 실제 아래 윤곽 → 포물선(최소제곱) 적합. **정점 기반 bin-max 는 비제약 삼각분할의 내부 정점에 속아 ∩/∪ 방향이 뒤집힘** | Stretchy P7/P12 |
| 입 중심/폭 | `mouth` bbox / 열린 입 변형의 윤곽(7점 두 베지어) | psd2live |
| 초기 머리 롤 | 눈 중심선 기울기 → 정렬 좌표계에서 변형 후 복귀 | psd2live |
| 좌우 | 연결 성분 중심 기준 분할 | See-through `part_lr_split` |
애니 얼굴 랜드마크(hysts/anime-face-detector 28점, 정면만)는 `eyewhite` 누락 시의 **교차검증/대체**로만.

> **좌우 규약 지뢰(V† + V):** See-through 코드 `part_lr_split` 는 뷰어 기준 왼쪽 성분에 `-r`, 오른쪽에 `-l` 을 붙인다(캐릭터 자신의 좌우). 타 파이프라인은 "See-through 의 맨 접미사 `eyewhitel` 과 psd2live `-l/-r` 이 거울상이라 12개 레이어가 `unknown`, 눈 깜빡임·시선 바인딩이 깨졌다"고 보고. → **자동 점검 필수:** `ParamEyeBallX` 를 돌려 두 눈이 같은 방향으로 움직이는지, `ParamEyeLOpen` 이 올바른 눈을 닫는지.

### 4.2 메시 (V†/U)
1. 알파 이진화(임계 4–8/255) + 2–3px 팽창(흰 이음선 방지: Stretchy 2px / Bunraku 3px) → 윤곽 추출(홀 보존) → Douglas-Peucker → 호 길이 재샘플.
2. 내부점: Bridson Poisson-disk, 밀도장 = f(경계 거리, 부품 클래스, 곡률), **경계:내부 ≈ 55:45**(Bunraku).
3. 삼각분할은 **제약 Delaunay(CDT)** — 비제약 Delaunator 는 오목부 코드 단락을 팽창으로 땜질 중(Stretchy). 라이브러리 라이선스(CDT/poly2tri/Triangle)는 **미확인, 선정 시 확인**(Triangle 은 상업 제약이 알려져 있음).
4. 후처리: 슬리버 제거, 내부 라플라시안 평활, 뒤집힘 검사.
5. **밀도는 부품 크기에 비례**: 눈·눈썹·속눈썹·입술은 리본형/윤곽 행 밴드, 머리카락은 가닥 방향 행, 얼굴은 이목구비 주변 조밀, 몸통·옷은 성김. (메시 간격 64 vs 32 가 결과 동일 — 부품이 간격보다 작아서: flowingduskpro V†)
6. **해상도가 품질을 좌우**: 768px 처리에서 얼굴 레이어가 102×127px 에 불과(V†). 512px 면 `head` 가 비어 머리 체인이 통째로 빠짐. → 분해 해상도 하한과 얼굴 레이어 최소 크기를 **사전 검사**.

### 4.3 디포머 계층 (V†)
Hiyori 역공학 구조: Body Z → Body Y → Breath → Body X → [Face Rotation] → **FaceParallax(단일 워프)** → 눈/눈썹/코·입 워프. 워프는 5×5 패치(6×6 제어점), 얼굴 회전은 AngleX×AngleY 9 키폼, AngleZ 는 회전 디포머가 아니라 머리카락 워프. psd2live: `DeformBodyXY` → `DeformBodyLean` → `DeformBodyZBreath` → 머리 회전 → head-follow 컨테이너 → 얼굴 격자/이목구비 변위(8×8), 앞/뒤 머리는 `Follow` + `Physics` 두 가닥, 서 있는 전신이면 다리 별도 루트. 격자가 이목구비 영역보다 성기면 근사 오차 → 보호 영역을 격자 한 칸만큼 확장(Stretchy A.6b).

### 4.5 눈·입·시선
- **눈:** (a) 기하 방식은 위 속눈썹 + 눈흰자 + 홍채가 분리되고 **눈꺼풀에 가려진 홍채 부분이 보존**돼 있을 때만 성립(psd2live 요구). (b) 변형 레이어 방식은 닫힌 눈 레이어 크로스페이드 — 소재가 없으면 템플릿(Anime2.5DRig) 또는 **이미지 편집으로 생성(image2live2d: 마스크 편집 2회 → OpenCV 로 입속·이빨·혀·눈꺼풀 측정)**. 닫으면 이마 아래 숨은 영역이 드러나 **인페인팅 잔상**이 보임 → 형태학적(blackhat/tophat) **국소 처리**가 효과적, 광범위 인페인트는 실패(V†). 아래 속눈썹 리그는 psd2live 미지원.
- **입:** 닫힌 입에서 입속은 기하로 못 만든다(psd2live 문서). 변형 레이어(열린 입 + 치아/혀) 필수. `ParamMouthOpenY × ParamMouthForm` 2축. **모음 A·I·U·E·O → (OpenY, Form) 점 매핑(U, 값은 튜닝 대상):** A(1.0, 0) I(0.3, +1) U(0.3, −1) E(0.6, +0.5) O(0.7, −0.6). 변형 레이어를 키폼 격자의 조각 이미지로 쓰는 하이브리드는 미검증.
- **시선:** `ParamEyeBallX/Y` = 홍채 평행이동(Hiyori 격자 폭의 약 9% / 높이 약 7.5%), **눈흰자를 클리핑 마스크**로.
- 눈/입 그룹은 `model3` 의 `EyeBlink`/`LipSync` 로 표시(내보내기 시).

### 4.6 머리카락·옷 물리·호흡
- **가닥 추정:** Anime2.5DRig 방식(열별 최하단 프로파일 → 상자 평활 k=41 → 돌출도 피크, minProm 10, 최대 6가닥, 뿌리 단단/끝 부드러운 2중 스프링) — 가장 단순하고 검증됨. 일반 형상은 중심선/주성분축에서 뿌리→끝 측지거리 L, `segments = clamp(round(L / (0.12·얼굴높이)), 1, 5)` (U).
- **키폼:** 워프 행마다 뿌리에서의 거리² 비례 변위로 끝만 크게.
- **pendulum 기본값:** 출발점은 앞머리 짧고 뻣뻣/뒷머리 길고 부드러움(길이·mobility·delay·accel). psd2live 소스의 기본값(뒷머리 길이 15·mobility 0.95·delay 0.8·accel 1.5·정규화 ±30 / 앞머리 길이 7.9·0.77·1.45·0.8·±10, 입력 AngleX 60 · AngleZ 60 · BodyAngleX 40 …)은 **GPL 코드에서 읽은 값이므로 복사하지 말고 우리 렌더에서 경험적으로 튜닝**한다.
- 입력은 AngleX/Z·BodyAngleX/Z, 출력은 `ParamHairFront/Back`. **물리 출력은 해당 파라미터에 이미 키폼이 있어야 눈에 보인다.**
- **호흡:** 가슴 압축 + 어깨 상승 + 아래 고정 (Stretchy 는 Hiyori 보다 약 10배 강해야 작은 캔버스에서 보임).

### 4.7 그리기 순서·클리핑·가림
- **정준 순서(태그 기반)를 기본**: `back hair < body < neck < face < 눈 계열 < front hair < headwear`. See-through 의사 깊이는 **충돌 시 보조/검증용** (Anime2.5DRig 도 PSD 순서 대신 이름 기반 깊이).
- **원본 픽셀 재투영(Kota-Ohno, V†):** 가시 영역은 원본 일러스트 픽셀로, 생성 픽셀은 **가려진 영역에만** 사용(IoU 0.987 정렬) → 선명도·원화 충실도 크게 개선, See-through 의 "AI 무늬" 완화. → **S4 의 핵심 후보.**
- **이음선 대책:** 앞머리 조각이 의복 픽셀을 머금어 같이 움직이는 현상, 큰 각도에서 목/머리 뿌리 잔상 → 레이어 단계에서 **오염 픽셀 제거 + 언더랩(겹침 여유)**, 업스케일은 그 **후에**(live2d-agent-kit). 애니용 ESRGAN 2종이 원화에서 오히려 멀어졌다(RMSE 41→96/53, V†).
- 사용자 보고 반복 실패: 포니테일이 뒷머리에 합쳐짐, 팔이 몸통에 병합(2048px v2), 목–상의 경계 → **"목을 상의에 합친 일체형"이 성공률이 높다**(Anime2.5DRig README 권고) → 옵션 제공.

**VLM 심판(수치 통과 후, V — image2live2d 설계):** 증거 = 원본 얼굴 + **실제 렌더한 포즈 시트**(양눈/단눈/반개구/전개구/웃음/감은 눈+입 벌림, 몸·호흡·팔·치마 극단), 단계 게이트 썸네일 384px / 최종 시트 1536px, temperature 0, 출력 스키마 `{identityPreserved, motionAdequate, score, issues[{code, severity, part, detail}]}`. **`passed` 는 코드가 계산**(신원 유지 + 움직임 충분 + major/critical 없음 모두 필요, 높은 점수가 심각 결함을 덮지 못함). **화이트리스트 수리**(`eye_residual/eye_seam`, `mouth_artifact`, `identity_drift`→원본에서 재편집·마스크 밖 원 픽셀 복원, `background_leak/layer_order`→재분해·클립, `joint_gap/motion_weak`→재바인딩, `other`→사람). 라운드 ≤3, 라운드별 보관, **개선 없으면 롤백**, 2라운드 무개선 정지, 감독 호출 24회 상한, 근거 부족 시 **`needs_review` — 공개 불가**.
- **한계(V):** psd2live 의 MCP 에이전트 실측표가 "머리카락 분리와 가림 영역 보완은 불가"라고 스스로 기록. **VLM 은 "이상 있음" 판정에는 쓸 만하나 정점 수준 수리는 못 한다** → 정점·키폼 수치는 절대 LLM 에게 맡기지 않는다.
- 참고 프로토콜(arXiv 2606.18451, 3D 메시 품질, 초록 수준): 고정 렌더 리그 + **서로 다른 두 VLM 계열 + 두 제시 순서 모두 질의해 순서 일관 판정만 채택**(위치 편향 보정), κ=0.66. **그대로 일반화하지 말고 우리 도메인 사람 라벨 50–100건과 상관을 먼저 검증.**

## 7. 사용자 prompt 는 무엇을 제어하나

**See-through 는 텍스트 조건이 없는 분해 모델**이다(태그는 고정 어휘 23종, 커스터마이즈는 코드 수정 필요 — 이슈 #21). 따라서 prompt 를 "분해에 넣는" 것은 불가능하다. 대신 **prompt → LLM → `RigSpec`(엄격 JSON) → 결정론적 컴파일러**로 흘린다 (V† 선례: Textoon, image2live2d):
| 제어 가능 | 예 |
|---|---|
| **표정 세트** — 어떤 변형 소재를 생성할지 | "웃는 얼굴, 윙크, 놀람 추가" (PNGAL "추가 표정", PachiPakuGen 7장) |
| **모션 스타일/강도** | "차분하게", "장난스럽게", "머리카락을 더 크게 흔들어" (psd2live `rigTuning`: 머리 전환·눈·눈썹·입·머리카락·몸·호흡 강도) |
| **리그 대상 선택** | 꼬리·날개·귀 흔들기, 치마 물리 유무 |
| **립싱크/음성 모드** | 마이크 음량 / 모음 매핑 |
| **레이어 힌트** | "포니테일은 별도 파츠", "모자는 고정" → VLM 이 제안, 사용자가 리뷰 UI 에서 확정 |
| **(후속) 레이어 단위 재텍스처** | "머리색을 파랗게", "교복을 드레스로" — **Bunraku 가 시연**: 의상 레이어를 자연어로 재텍스처해도 메시·애니메이션은 byte 단위로 재사용 |
| 입력이 없을 때(후속) | 이미지 생성 모델로 시작 이미지 생성 (image2live2d 단계 1) |
**제어 불가:** 어느 부품을 분리할지(분해 단계) — 사후 휴리스틱(`heuristic_partseg.py` 깊이/좌우 분할) 또는 VLM 재분류로만. Bunraku Stage 1 은 레이어별 캡션 조건(드롭아웃 50%)이 있어 "부위 지시" 가능성이 있으나 미공개.
- 모션 생성(V† 공백): **Live2D 리그에서 텍스트→모션을 다룬 공개 방법은 찾지 못했다.** 구조 제안(U): LLM 은 `{name,duration,loop,tracks:[{param,keys:[{t,v,ease}]}]}` **스펙만** 작성 → 컴파일러가 클램프·가속/저크 제한·루프 이음 보정 → 렌더/물리 시뮬 + VLM 점검 → 실패 시 수치 진단을 되돌려 재작성(≤N회).

## 8. 품질 티어 (근거 기반, 수치 확률은 근거가 없어 제시하지 않음)

| 티어 | 내용 | 현재 달성성 |
|---|---|---|
| **Tier 1 (MVP 목표)** | 눈 깜빡임 + 입 열림/닫힘(**생성 변형 소재 필수**) + 호흡 + 앞/뒤 머리 흔들림 + **작은 머리 회전(±15° 시차)** + 시선 + idle. 전제: 정면 직립 단일 인물 | 분해 성공 시 자동 가능. **성공률 통계는 공개된 바 없음 → M0 에서 직접 측정** |
| **Tier 2** | 전체 머리 XY(±30–45) 의 그럴듯한 3D 느낌 + 표정 프리셋 + 몸 회전 + 팔 IK | 해석 모델 범위까지는 가능, **생성 키프레임 기반은 연구 필요** |
| **Tier 3 (프로급)** | Hiyori 급(134 메시 / 104 디포머 / 70 파라미터), 미세 표정, 전신 동작, 손가락 | **불가(현시점, 누구도 못 함)** |
제품 약속은 Tier 1 로. **"할 수 없는 것을 정직하게 말하는 capability report"를 모든 퍼펫에 붙인다**(image2live2d 선례, 입 소재가 없으면 "lipsync: degraded").
