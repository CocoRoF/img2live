# 02. 최신 생성 모델로 파이프라인의 생성 단계를 할 수 있는가 (2026-10-02 조사)

근거: 에이전트 조사 `research_models.md`(≈110개 출처) + 직접 재확인(Bunraku 저장소·논문, See-through 이슈 #43).
표기: **(V)** 1차 출처를 열어 확인 / **(U)** 2차 자료·미확인. 가격·상한은 확정 전 원문 재확인.

## 0. 한 줄 결론

> **된다. 단, "한 번에 PSD 를 뽑아 주는 범용 API"는 없고, 단계별로 가장 맞는 모델이 다르다.**
> - 레이어 분해 + 가려진 부분 인페인팅 → **애니 전용 공개 모델(See-through V3)이 이미 최선**. 범용 API 는 이 단계에서 그보다 낫다는 근거가 없다.
> - 눈 감김·입 모양 같은 **부위 변형** → **최신 범용 편집 모델이 가장 잘 맞는 자리**(OpenAI gpt-image-2.5-sunburst 가 편집 아레나 1위). 단 "크롭 → 편집 → 마스크 합성" 구조여야 한다.
> - 머리 회전 → **새 시점 그림을 생성하지 말고 메시 워프**(측정된 근거가 없고 Bunraku 도 측면에 약함).
> - **API 결과로 우리 모델을 학습시키면 안 된다**(OpenAI·Google·BFL·xAI·BytePlus 약관의 경쟁 모델 금지).

## 1. 지금 시점의 지형 (확인된 것만)

### 1.1 OpenAI (V)
- 최신 이미지 모델: `gpt-image-2.5-sunburst`(편집 정밀도 우선), `gpt-image-2.5-flare`(빠름), 2026-09-08 출시. 이전 `gpt-image-2`(04-21), `gpt-image-1.5`·`1-mini` 는 **2026-12-01 종료**.
- **LLM(GPT-6/5.x)이 이미지를 직접 출력하지는 않는다.** Responses API 에서 LLM 이 `image_generation` 도구를 호출하면 gpt-image-* 가 그린다. (→ "GPT 로 이미지 생성" = gpt-image-* 호출)
- 투명 배경: `background:"transparent"` 가 2026-08-20 preview 로 추가. 단 **편집 시 윤곽을 다시 그린다**는 2차 보고가 있어 분해 레이어끼리 정합이 필요한 용도에는 부적합(U).
- 마스크 편집은 가능하나 "마스크 모양을 완전히 따르지 않을 수 있음"(공식 가이드). 공식 가이드의 직접 권고: **"픽셀이 동일해야 하면 승인된 편집 결과를 원본에 합성하라."**
- 가격(토큰제): 이미지 출력 $30/M. 1024² 한 장 ≈ low $0.006 / medium $0.013 / high $0.053 (요율 V, 토큰 수 U). 속도 한도 Tier1 은 5 IPM — **공개 서비스는 Tier4~5 가 되어야 의미**.
- 편집 아레나(2026-09-29): 2.5-sunburst **1위(1522)**, 2.5-flare 2위, gpt-image-2 3위 (V).

### 1.2 Google (V)
- Nano Banana 2(`gemini-3.1-flash-image`, $0.045~0.151/장), Nano Banana Pro(`gemini-3-pro-image`, $0.134~0.24), Lite(`…flash-lite-image` $0.0336). Imagen 은 **종료**, 2.5-flash-image 는 오늘 종료 예정.
- **마스크 입력 파라미터가 문서에 없다**(프롬프트 기반 편집). 투명 PNG 도 문서에 언급 없음(2차: 알파 없음).
- 약관: **18세 미만이 접근 가능한 앱 금지**, 경쟁 모델 개발 금지. 위반 누적 시 **다른 Google 서비스까지 영구 차단**까지 에스컬레이션(V~).
- 아레나: Pro 10위(1390), NB2 12위(1387).

### 부위 변형(②)에 대해 정직하게
- **애니 부위 변형만 따로 측정한 벤치마크는 공개되어 있지 않다.** 있는 것은 일반 편집 선호도(아레나), 벤더 가이드, 커뮤니티 도구의 작업 방식뿐.
- 커뮤니티 사례(U): PachiPakuGen 은 외부 에이전트(Claude/GPT 이미지 생성)로 FACS 기반 모음 7종을 만들고 "대부분 좋다"고 보고, PNGAL 은 See-through → 눈/입 마스크 → **Qwen-Image-Edit-2511(ComfyUI)** → RIFE 보간.
- 기본 동작이 "얼굴 영역 전체 재그림"이므로 **(크롭 → 편집 → 알파 마스크 합성 → 경계 블렌딩)** + **자동 검사(마스크 밖 SSIM, 눈동자 색, 선 굵기) → 재시도** 구조가 필요하다. 이는 OpenAI 가이드가 직접 권하는 방식이다.
- "한 장에는 움직일 정보가 없다. 앞머리 뒤의 눈, 입 안, 옷에 가린 목은 추정할 수 없고 '그럴듯한' 보완은 제작자 의도와 다르다"(커뮤니티 후기) → **자동 80% + 사용자가 쉽게 고치는 20%** 로 설계.

## 3. 가장 가까운 선행 연구: Bunraku (직접 확인)

arXiv 2607.27348 (2026-07-29), 프로젝트 페이지 https://bunraku-live2d.github.io/ — **"단일 일러스트 → 순서 있는 RGBA 레이어 + 레이어별 변형 메시 + 파라미터 구동 keypose 정점 변위"**.

- Stage 1: **Qwen-Image-Layered 를 Live2D 10K 모델로 SFT**, 자체 "8-class / 32-subclass 기관 분류"(hair, face skin, eyes, mouth, head accessory, torso, arms, lower body). 신체 부위로 분류하지 않고 가방·치마 패널 같은 비해부 요소도 별도 시트로 예측.
- Stage 2: 알파에서 메시 자동 생성(임계 α>4/255, 3px 팽창, 외곽선 호장 샘플링 + 지터 내부 격자 + Delaunay, 레이어당 약 83정점/112면). **5.1M 파라미터 트랜스포머**가 "모든 레이어의 모든 정점 = 토큰, 레이어 경계를 넘는 self-attention" 으로 keypose 변위를 **joint** 예측. 파라미터당 keypose 2~3개, 핵심 8파라미터(머리/몸 각도, 입·눈 개폐), 런타임은 양쪽 keypose 사이 **선형 블렌드, 다중 파라미터는 가산**.
- 수치(V): Stage1 α-IoU **0.950** (See-through 0.873 / Qwen-Image-Layered 0.916 / SAM 0.851), 레이어 순서 정확도 0.674 (See-through **0.266**). Stage2 방향 코사인 평균 0.768 / 중앙값 0.828, 50개 중 31개가 ≥0.80.
- **저자 자신의 결론: "Stage 1(분해)이 병목".** 같은 Stage 2 를 See-through 분해에 적용하면 야생 일러스트 13장 중 약 7장이 실패(팔다리·의상 누락 등).
- 한계(V): 다중 파라미터 가산 시 "레이어가 벌어짐"(진폭 과대: 중앙 비율 1.234), 측면·후면·단축 자세에서 저하, 파라미터 간 결합 없음.
- 학습 데이터: 인터넷 공개 Live2D 모델 8,884개 (**권리 처리 명시 없음**, 공식 Web SDK로 추출). 데이터셋은 "학술 접근·상업 라이선스는 문의".
- **코드/가중치: 없음.** GitHub `SparcAI-Inc/Bunraku` 는 README(722바이트) 한 장짜리 자리 표시자, LICENSE 없음, 마지막 푸시 2026-07-31 (직접 확인). 프로젝트 페이지는 "code is released on GitHub" 라고 쓰지만 실제로는 비어 있다.
- 출력 포맷: 논문은 "Live2D Cubism 런타임이 필요로 하는 정보를 정확히 담은 구조화된 Live2D 에셋"이라고만 하고 **.moc3 내보내기는 서술하지 않음**. 자체 WebGL 뷰어(30fps)로 렌더.

**우리에게 주는 것:**
1. 문제 정의가 같다 — "단일 일러스트 → 레이어 → 메시 → 파라미터 구동 변위". **방법론 차용 대상으로 적합**, 코드 재사용은 불가(우리가 구현).
2. **Live2D 의 키폼 = "파라미터 키 값에서의 정점 변위 + 선형 보간"** 이므로, Bunraku 의 keypose 표현은 Cubism 모델과 동형이다. 우리 중간 표현(IRR)을 같은 구조로 만들면 렌더러·내보내기가 단순해진다(→ `03`).
3. **분해가 병목**이라는 증언 → 우리 R&D 의 첫 투자는 분해 품질(See-through 파인튜닝/보강 + 사용자 보정 UI).

- 애니풍 캐릭터는 성인이라도 어려 보이는 경우가 많아 API 필터 오탐이 예상된다 → **API 에 의존하면 서비스 가용성이 벤더 정책에 종속**된다.
- → **MVP 의 부위 변형은 자체 호스팅(Qwen-Image-Edit-2511 등)을 기본**, API(sunburst/NB2)는 품질 상한을 재는 기준선 + 선택 어댑터로.

## 5. 권고 (이 조사에서 나오는 결정)

1. **1단계는 See-through V3 로 고정**하되 **교체 가능한 모듈 계약**(`decompose(image) → layers[+depth+order]`)으로 감싼다. 장기적으로 Bunraku 식 파인튜닝(Qwen-Image-Layered 기반, Apache-2.0)으로 갈아탈 수 있게.
2. **부위 변형 = 어댑터 패턴**: `edit_region(crop, mask, instruction, refs) → rgba` 를 인터페이스로, 구현체를 ①Qwen-Image-Edit-2511(자체, 기본) ②gpt-image-2.5-sunburst(품질 기준선) ③Nano Banana 2 ④FLUX 3 Image 로. **한 캐릭터는 같은 어댑터로 끝까지**(폴백이 일관성을 깨므로).
3. **머리 회전은 메시 워프**. 시점 생성은 선택 기능(연구 트랙).
4. **자체 평가 세트를 가장 먼저**: 50~100 캐릭터 × 변형 10종, 마스크 밖 SSIM·정체성 LPIPS·수작업 합격률로 위 4개 어댑터를 같은 조건에서 비교. (→ `06` 평가 계획)
5. **API 산출물로 학습하지 않는다.** 학습/파인튜닝용 데이터는 오픈 가중치 모델 또는 라이선스가 정리된 Live2D 데이터에서만 만든다.
6. 모든 업로드에 **자체 안전 게이트**(→ `04`).
