# 06. 평가 계획 — 무엇을 어떻게 재서 "된다/안 된다"를 판정하나

**이 프로젝트의 첫 번째 산출물은 코드가 아니라 측정 장치다.** 조사에서 반복해서 확인된 사실: ① 애니 부위 변형(눈 감김·입 모양)을 정량 비교한 공개 벤치마크가 없다(`02`) ② 자동 리그 성공률 통계가 공개된 곳이 없다(`03`) ③ VLM 심판은 우리 도메인에서 검증된 바 없다. 그러므로 **M0 에서 벤치마크 세트와 평가 하니스를 먼저 만들고**, 모든 설계 결정(어댑터 선택, 컴파일러 선택, 서비스 약속)을 이 숫자로 한다.

수치 임계값은 전부 **임시(U)** — M0 실측 후 재보정한다.

## 2. 단계별 지표 (계층형)

### Tier 0 — 결정론적 불변식 (매 잡, 비용 0, CI·프로덕션 겸용)
- **레이어 인벤토리:** 기대 파트가 존재하는지, 빈 레이어 없음.
- **재구성:** 레이어 합성 vs 원본 PSNR/SSIM/LPIPS, 알파 합집합 vs 입력 알파 IoU ≥ 0.98(U). (논문 Table 1 이 같은 계열 — LPIPS 0.155, PSNR 18.30, SSIM 0.923, FID 18.37, Mask Dice 0.386 — **우리 평가를 논문과 비교 가능하게 맞춘다**)
- **파트 건전성:** 눈 쌍(연결 성분 2개), 손 ≤2, 좌우 면적비 ∈[0.5,2], 홍채가 흰자 마스크 안에 ≥95%, 깊이 순서 단조성.
- **리그 건전성**(`03` §5): 삼각형 뒤집힘 0, 최대 신장비 ≤2.5(U), 실루엣 구멍 면적비, 홍채 유출 0, 눈 개폐 단조성, 파라미터 스윕 연속성, **좌우 방향 점검**, **다중 파라미터 가산 진폭**, 목표 기기 ≥55fps.

### Tier 1 — 정체성 보존
입력 vs 중립 렌더, 중립 vs 극단 포즈의 DINOv2/CLIP 임베딩 코사인. *참고: 논문이 인용하는 DACoN("DINO for anime")은 일반 DINOv2-Large 를 쓰는 채색 방법이지 애니 전용 임베딩이 아니다 — 표준 애니 정체성 지표는 못 찾았다(V~). 임계값은 보정 필요.*

### Tier 2 — VLM 심판 (키프레임 시트)
중립/좌우 깜빡임/입 A·I·U·E·O/머리 yaw ±20·±30/pitch/미소를 512px 격자로 렌더 → 루브릭(정체성, 아티팩트, 움직임 개연성, 가려짐 처리) 1–5점 + A/B 쌍비교. **서로 다른 두 VLM 계열 + 두 제시 순서 모두 질의, 순서 일관 판정만 채택**(arXiv 2606.18451 프로토콜, 초록 수준 V~). **그대로 일반화하지 말고 우리 도메인에서 사람 라벨 50–100건과 상관(Spearman/κ)을 먼저 검증한다.** 검증 전에는 VLM 점수를 "판정"이 아니라 "필터"로만 쓴다.

### Tier 3 — 정답 기반
Live2D 샘플(공식 무료)에서 `CubismPartExtr`(See-through 가 데이터 구축에 쓰는 C++ 도구, Cubism Native SDK 5-r.4.1 기반)로 파트별 정답 레이어 추출 → 합성 이미지를 입력으로 → 파트별 IoU/Dice, 가려진 영역(amodal) LPIPS/PSNR, 깊이 순서 Kendall τ. *테스트 셋 공개 여부는 확인 못 함. Cubism SDK 를 내려받는 작업이므로 **clean-room 규칙(`04` §2)을 지키는 팀원은 이 작업을 하지 않는다**(평가 전담자 분리).*

## 3. 변형 소재 생성 평가 (가장 중요한 빈칸)

대상: 닫힌 눈(L/R), 웃는 눈, 입 A·I·U·E·O, 닫힌 입, 눈썹 변형 등 **캐릭터당 10~12종**. 비교 어댑터: ①Qwen-Image-Edit-2511(자체 호스팅) ②gpt-image-2.5-sunburst ③Nano Banana 2 ④FLUX 3 Image (+ 템플릿 폴백 Anime2.5DRig 방식을 기준선으로).

| 지표 | 정의 |
|---|---|
| **마스크 밖 보존** | 편집 영역 밖 SSIM/PSNR(합성 후), 경계 블렌딩 아티팩트 |
| **정체성** | 눈동자 색(ΔE), 하이라이트 위치, 선 굵기 분포, 속눈썹 곡선, 피부톤 — OpenCV 측정(image2live2d 방식) |
| **의도 충족** | 감은 눈이 실제로 감겼는지, 입이 해당 모음 형태인지(VLM + 규칙: 입 내부 면적·치아/혀 존재) |
| **조합 일관성** | 한 캐릭터의 여러 변형이 서로 같은 스타일인지(캐릭터 내 분산) |
| **합격률(사람)** | 10종 중 사용 가능 비율 — **최종 의사결정 지표** |
| 비용·지연·거부율 | API 거부(`02` §4), 재시도 횟수, $/캐릭터 |
**자동 재시도 규칙(U):** 마스크 밖 SSIM < 임계 또는 눈동자 ΔE > 임계 → 재시도(≤3) → 실패 시 템플릿 폴백 또는 `degraded` 표시.

## 4. 합격 기준 (임시 제안 — M0 후 보정)
| 단계 | 질문 | 임시 기준(U) |
|---|---|---|
| 분해 | 야생 입력에서 사람이 "수정 없이 또는 가벼운 수정으로 쓸 만"한 비율 | In-domain(정면 전신 애니) 70%+ / 나머지는 **조용한 실패가 아니라 거절 또는 needs_review** |
| 변형 | 10종 중 합격 비율 | 어댑터별 비교 후 자체 호스팅이 API 의 **80% 이상**이면 자체 호스팅 채택(정책 리스크 때문) |
| 리그 | Tier 0 불변식 통과율 | **100%**(불변식 실패 퍼펫은 공개 불가) |
| 리그 | Tier-1 기능(깜빡임·입·호흡·머리카락·±15° 회전) 시각 합격 | 벤치 세트의 60%+ (기존 OSS 기준선 대비 개선 폭도 함께 보고) |
| VLM | 사람 라벨과 상관 | κ ≥ 0.6(U, 참고 프로토콜 0.66) 이상일 때만 판정 권한 부여 |
| 성능 | 목표 기기 렌더 | 데스크톱 ≥55fps, 중급 모바일 ≥30fps |
| 지연 | 업로드→뷰어 | 변형 포함 **≤ 8분**, 진행률 스트리밍 필수 |
숫자는 모두 **근거가 없는 출발점**이다. M0 에서 기존 OSS(psd2live·image2live2d·Stretchy·Anime2.5DRig)를 같은 세트에 돌려 **"기존 대비 얼마나 나은가"** 를 기준으로 재설정한다.

## 5. 평가 하니스 (M0 산출물)
- `bench/` : 입력 세트 매니페스트(출처·라이선스·사용 범위 필수 필드), 정답 레이어(샘플), 라벨(사람 합격/불합격).
- `eval/` : 위 지표 계산기, 실행 러너(어댑터·컴파일러를 플러그인으로), **회귀 대시보드**(커밋 해시 × 지표). 서비스 코드와 동일 컨테이너에서 CI 로 실행.
- **재현 규칙:** 모든 결과에 (모델 리비전 해시, seed, 코드 커밋, GPU 종류)를 기록. GPU 비결정성 때문에 비트 동일을 기대하지 않고 **통계(분포)로 비교**.
